Overview

awdiscord/README 
Putting an agent in a Discord server usually means one of two bad shapes: a script driving a person's account, which breaks Discord's terms and gets the account banned, or a bot that answers anyone as fast as they can type and acts on its own judgement. What is missing is the boring middle: an install link that asks for almost nothing, per-user and per-server limits, and a way for the agent to ask a human before it does something, with an answer it can trust.

awdiscord

Put any agent on Discord as a real bot, with an operator in the loop.

An agent behind an OpenAI-compatible endpoint (an adk serve agent, llama.cpp, vLLM, Ollama, a gateway) becomes a Discord bot with three slash commands, rate limits, and approval buttons that only your operators can press.

```bash
pip install "awdiscord[gateway]"
export DISCORD_BOT_TOKEN=...                       # from the Discord developer portal
export AWDISCORD_AGENT_URL=http://127.0.0.1:8080/v1
awdiscord install-url --app-id <your application id>   # send this link to a server admin
awdiscord run
command what it does
/ask question [persona] [private] the agent answers; private shows only you
/share posts your last answer in the channel
/status is the agent up, which personas exist

Rails

  • Bot tokens only. Every request is sent as Authorization: Bot <token>, and the runtime asks Discord who the token belongs to before anything else. A user account is refused. Driving a person's account ("self-bot") is against Discord's terms.
  • Least permission. The install link asks for bot + applications.commands and four permissions: view channel, send messages, embed links, read message history. install_url() refuses administrator, manage-server, manage-roles, manage-webhooks, ban, kick and mention-everyone.
  • Rate limits. Token buckets per user, per server and for the whole bot; a request must find room in all three, and a refusal says how long to wait.
  • Mentions off. Every answer goes out with allowed_mentions: {parse: []}, so an agent cannot ping @everyone.
  • Approvals. A card with Approve / Deny buttons. The button id carries an HMAC of the approval id and the verb, only user ids in AWDISCORD_OPERATORS count, a decision is taken exactly once, and the result is POSTed to your callback with an X-Awdiscord-Signature header (HMAC-SHA256 of the body under the same secret).

Approvals from your own code

Run the bot with an inbox, then raise cards from anything on the same machine:

```bash
export AWDISCORD_OPERATORS=<your user id>
export AWDISCORD_APPROVAL_SECRET=$(python -c "import secrets;print(secrets.token_hex(32))")
export AWDISCORD_INBOX_PORT=8371 AWDISCORD_INBOX_TOKEN=<a long random string>
awdiscord run &
awdiscord approval "Publish the release notes?" "v1.4 notes are drafted" \
    --callback http://127.0.0.1:9000/decided

Without AWDISCORD_APPROVAL_CHANNEL the card is sent to each operator by DM.

Use the pieces alone

```python
from awdiscord import install_url, RateLimiter, ApprovalDesk, post_webhook, Dispatcher

install_url("123456789012345678")
post_webhook("https://discord.com/api/webhooks/...", "deploy finished")

Dispatcher takes the interaction JSON Discord sends and returns the response JSON, with no network, so the bot's behaviour is testable with plain dicts.

Configuration

variable meaning
DISCORD_BOT_TOKEN / AWDISCORD_TOKEN the bot token
DISCORD_APP_ID / AWDISCORD_APP_ID application id (looked up from the token if unset)
AWDISCORD_AGENT_URL, AWDISCORD_AGENT_MODEL, AWDISCORD_AGENT_KEY the agent
AWDISCORD_PERSONAS_DIR <name>.md or <name>/SOUL.md files become /ask persona: choices
AWDISCORD_DEFAULT_PERSONA persona used when none is chosen
AWDISCORD_CA_BUNDLE CA file for an agent served over a private CA
AWDISCORD_OPERATORS, AWDISCORD_APPROVAL_SECRET enable approvals
AWDISCORD_APPROVAL_CHANNEL post cards here instead of DMing operators
AWDISCORD_INBOX_PORT, AWDISCORD_INBOX_TOKEN, AWDISCORD_INBOX_HOST local inbox
AWDISCORD_DEV_GUILD also register commands on one server (instant, for testing)
AWDISCORD_STATE_DIR where approvals are stored (default ~/.awdiscord)

awdiscord --self-test proves every rail offline and exits non-zero if one does not hold.
